# Игра cooking ("Повар")

3D-игра про работу повара в стиле PlateUp! и Overcooked: игрок готовит блюда на кухне и сдаёт их в окно выдачи, ИИ-официант относит их клиентам в зале. Игра подключена к порталу готовой веб-сборкой в изолированном фрейме (`docs/adding-game.md`, раздел "Игра на Unity или three.js"; протокол обмена в `docs/game-bridge-protocol.md`). Три уровня: easy (3:00), medium (4:00), hard (5:00).

Все команды ниже запускаются из папки `web`. Пути в разделах про код даны от `games/cooking/src/`, если не сказано иное.

## Где что лежит

| Что | Где |
| --- | --- |
| Портальная часть: манифест, тексты витрины, модуль | `games/cooking/` |
| Исходники игры (Vite, TypeScript, three.js) | `games/cooking/` |
| Результат сборки (хранится в git, как у `city-builder`) | `public/game-builds/cooking/` |
| Кадры превью для библиотеки игр | `public/game-previews/cooking/` |
| Общие типы и интерфейсы между областями | `contracts.ts` |
| Симуляция без DOM и three.js: кухня, клиенты, смена, навигация, официанты | `sim/` |
| Данные трёх уровней и параметры баланса | `config/levels/` |
| Эталонный бот и проверка seed | `bot/` |
| Ввод, рендер, HUD | `input/`, `render/`, `hud/` |
| Весь отображаемый текст игры | `texts/` |

Логика игры не знает о браузере: `sim/` не импортирует three.js и DOM, поэтому вся механика проверяется тестами vitest без окна браузера. Числа баланса лежат только в параметрах уровня (`LevelParams`), в коде симуляции их нет.

## Управление

| Действие | Клавиатура и мышь | Сенсорный экран |
| --- | --- | --- |
| Идти | `W A S D` или стрелки | стик: коснитесь левой половины экрана и ведите палец |
| Взять или положить | `E` или левая кнопка мыши | верхняя кнопка справа ("Взять") |
| Резать (удерживать) | `Q` или правая кнопка мыши | нижняя кнопка справа ("Резать", удерживать) |
| Пауза | `Esc`, на паузе `Esc` продолжает игру | кнопка паузы вверху справа |

Клавиши читаются по физическому положению (`event.code`), поэтому русская раскладка не мешает. Повар смотрит в одно из восьми направлений и действует на станцию перед собой: она подсвечивается. На телефоне в портретной ориентации игра просит повернуть экран.

Подсказки управления лежат в `texts/controls.ts`, остальные тексты HUD в `texts/hud.ts`.

## Правила игры

- Клиенты приходят по расписанию дня, которое строится из seed в начале смены. Если свободного стола нет, группа встаёт в очередь на улице. За 60 секунд до конца таймера новые клиенты не приходят, на экране появляется баннер.
- Когда группа села, каждый её член делает заказ. Заказы показаны в углу экрана карточками по столам. На телефоне вместо карточек столов показана сводка по блюдам: плитка блюда и в кружке число порций, которые ждут все столы.
- Блюдо собирается на тарелке и сдаётся в окно выдачи. Окно принимает только готовое блюдо, на которое есть открытый заказ. Официант сам берёт блюдо и несёт его к столу. Подача засчитывает цену блюда и чаевые, зависящие от остатка терпения.
- Уход клиента из-за истёкшего терпения (в очереди или за столом) сразу завершает смену провалом. После кнопки "Продолжить" портал получает результат с `completed = false`.
- Уровень пройден (`completed = true`), если к концу таймера все клиенты дня обслужены (блюдо подано; доедать не нужно). Если последний клиент обслужен раньше, смена завершается досрочно.
- Всё, что лежит в руке, считается одним предметом: тарелка с содержимым тоже. Готовое на плите и в духовке подгорает, если вовремя не забрать. Сгоревшее годится только в урну.

Пять блюд кампании:

| Блюдо | Как приготовить |
| --- | --- |
| Окорок | сырую ветчину в духовку; готовую на тарелку |
| Стейк | целый сырой стейк сразу на плиту (резать не нужно); готовый стейк на тарелку |
| Бургер | стейк на любую поверхность, нарезать, пожарить; держа котлету, взять булочку из ящика, затем положить готовый бургер на тарелку |
| Веган бургер | нарезать картофель и морковь на любой поверхности, пожарить вместе; держа овощную котлету, взять булочку и соединить |
| Рагу | снять кастрюлю с плиты, налить воду в раковине и вернуть на плиту, нарезать картофель, морковь и лук и положить в кастрюлю; с полным набором плита включается сама, выключается после варки, рагу даёт несколько порций |

Собирать блюда можно в руках или на любой свободной поверхности. Например, держа жареную котлету, нажмите E у ящика булочек, чтобы взять булочку и соединить её с котлетой. Чтобы подать блюдо, подойдите к стойке тарелок с ингредиентом или блюдом, которое входит в рецепт: предмет окажется на тарелке в руке. Также можно поставить тарелку на поверхность и добавлять содержимое в руку. Тарелка принимает только то, что подходит к одному из блюд текущего дня.

Сковород нет: котлеты и стейк жарятся прямо на плите, а свободная плита принимает кастрюлю (в день рагу кастрюля стоит на своей плите с начала смены, отдельного стола с кастрюлей нет). Готовка на плите, в духовке и кастрюле занимает 80% прежнего времени. Разделочная доска ускоряет резку на 20%, но резать можно на любой поверхности. Во время готовки зелёная полоса показывает готовность, красная показывает время до подгорания. Рагу не пригорает: после варки плита выключается.

### Кампания и рецепты

Перед первой сменой показывается пролог о работе поваром и цели недели. В каждой сложности пять рабочих дней; меню пополняется по одному блюду в порядке: окорок, стейк, бургер, веган бургер, рагу. Вместе с меню по дням появляется мебель кухни (раздел "Планировка кухни"). Сложности отличаются длительностью смены и терпением клиентов, а не доступностью рецептов. Полностью обслужите гостей каждого дня, чтобы перейти к следующему.

Игра сохраняет, какие блюда игрок готовил своими руками, и сколько дней прошёл на каждой сложности. Перед сменой показываются рецепты блюд из меню дня, которые игрок ещё не готовил. Подсказка содержит название блюда и анимации шагов; её можно пролистать, пропустить или закрыть клавишей Escape. GIF всех шагов начинают грузиться сразу при создании HUD (а для нового блюда следующего дня уже на экране итога дня), поэтому шаги открываются без пустого кадра (`hud/tutorialPreload.ts`). В сообщении о проигрыше указывается блюдо или очередь, но не номер стола.

Снаружи ресторана тротуар с цветочными ящиками, кадки у входа, фонари, дорога с переходом и проезжающими машинами, деревья и дома через дорогу. Здание Г-образное: кухня стоит у передней стены, ближе к камере, а севернее неё газон с живой изгородью вдоль стен, кустами и цветами (только декор). Внутри полки, утварь, окна, картины, ковры и сервировка столов. Небо и освещение постепенно меняются с утра к вечеру по таймеру смены: к концу смены свет теплеет и загораются фонари и бра.

Графика устроена так (папка `render/`): окружение строит `environment.ts`, детали интерьера `interior.ts`, процедурные текстуры (доски, плитка, трава, картины, значки эмоций) `textures.ts`, частицы (пар, дым, искры, пузыри, крошки) `effects.ts`. Мелкие детали склеиваются в меши по материалам (`batch.ts`), поэтому декор и персонажи рисуются малым числом вызовов. Тени солнца запекаются один раз на первом кадре: стены и мебель не двигаются, у персонажей свои пятна-тени. Декор не создаёт ложных препятствий: настенные вещи висят выше голов или в зазоре у стены, на полу лежат только плоские коврики.

## Планировка кухни

Кухня 6 x 5 клеток (x от 0.5 до 6.5, z от 5.5 до 10.5, юго-западный угол здания у передней стены) вместо прежних 7.5 x 10: прежняя кухня тратила на ходьбу втрое больше, чем нужно, а её южная половина пустовала. Освободившееся место отдано улице: здание Г-образное, кухня придвинута к передней стене (ближе к камере, её нижний ряд виден поверх низкой передней стены), а севернее кухни за её северной стеной газон с кустами (зона `garden`: пол не рисуется, видна трава окружения). `createSharedShell` в `config/levels/sharedLayout.ts` укорачивает северную и западную стены и заново собирает разделяющую стену с окном выдачи напротив рядов 3 и 4 кухни; крайние куски короче 2 рендер сжимает по длине. Справа за стеной с окном выдачи зал на всю глубину здания. Прохода из кухни в зал нет: блюда уходят через окно, поэтому проверки достижимости разделены (из старта повара все станции, из точек ожидания официантов все цели зала, `config/levels/reachability.ts`).

```
         1          2          3          4          5          6
ряд 1:  прилавок   лук        раковина   плита+к.   духовка    ветчина
ряд 2:  .          .          .          .          .          .
ряд 3:  .          морковь    картофель  доска      тарелки    .        <- окно выдачи
ряд 4:  .          .          .          .          .          .        <- окно выдачи
ряд 5:  прилавок   урна       плита      булочки    плита      стейк
```

Проходы (ряды 2 и 4 и концы ряда 3) образуют кольцо вокруг острова (ряд 3). К каждой станции подходят прямо, без подхода по диагонали; к острову с двух сторон. Духовка, самая высокая станция, стоит у северной стены и не закрывает кухню от камеры.

Мебель появляется по дням кампании и дальше стоит на своём месте (`StationConfig.fromDay`, `config/levels/campaign.ts`):

| День | Меню | Появляется |
| --- | --- | --- |
| 1 | окорок | духовка, два прилавка, урна, ящик ветчины, стол с тарелками |
| 2 | + стейк | ящик стейков, две плиты для жарки |
| 3 | + бургер | стол с разделочной доской, ящик булочек |
| 4 | + веган бургер | ящики картофеля и моркови |
| 5 | + рагу | ящик лука, раковина, плита с кастрюлей |

### Как выбрана расстановка

Для каждого блюда разобрана цепочка станций, которую повар проходит от окна выдачи до окна (ожидание готовности не считается: в это время повар занят другим блюдом):

| Блюдо | Цепочка |
| --- | --- |
| Окорок | окно, ящик ветчины, духовка, тарелки, окно |
| Стейк | окно, ящик стейков, плита, тарелки, окно |
| Бургер | окно, ящик стейков, доска, плита, булочки, тарелки, окно |
| Веган бургер | окно, картофель, доска, плита, морковь, доска, плита, булочки, тарелки, окно |
| Рагу (на две порции) | окно, плита с кастрюлей, раковина, плита с кастрюлей, затем трижды "ящик овоща, доска, кастрюля"; порция: тарелки, кастрюля, окно |

Самые частые переходы на одно блюдо меню пятого дня: тарелки и окно (0.8: каждое блюдо, кроме второй порции рагу, кончается этим шагом), доска и плита (0.6), плита и булочки, булочки и тарелки (по 0.4), ящики картофеля и моркови и доска (по 0.3), доска и кастрюля (0.3), ветчина и духовка, духовка и тарелки (по 0.2). Отсюда правила: тарелки вплотную к окну, доска между ящиками овощей и плитами, булочки между плитами и тарелками, кастрюля напротив доски, раковина рядом с кастрюлей, ветчина рядом с духовкой.

Сами клетки выбраны перебором перестановок 16 станций по 16 местам (обмены пар до локального минимума с 30 случайными стартами). Цель: средний путь на блюдо пятого дня с весом 2 плюс средний путь дней 1-4, мелкими весами урна рядом с плитами и прилавок рядом с тарелками и булочками, духовка только у северной стены. Каждый день использует только свою мебель, поэтому ранние дни тоже короткие: окорок первого дня проходится почти на месте.

Средний путь повара на одно блюдо меню (единицы мира по навигационной сетке; повар проходит 3.6 единицы в секунду):

| День | Прежняя кухня | Новая кухня |
| --- | --- | --- |
| 1 | 15.3 | 2.5 |
| 2 | 18.4 | 2.4 |
| 3 | 22.9 | 3.2 |
| 4 | 27.5 | 4.7 |
| 5 | 27.6 | 5.4 |

По блюдам на пятый день: окорок 15.3 и 2.5, стейк 21.5 и 2.4, бургер 31.8 и 4.7, веган бургер 41.4 и 9.1, рагу 27.8 и 8.6. Пересчитать отчёт после правки расстановки (из папки `web`):

```
COOKING_ROUTE_REPORT=1 npx vitest run games/cooking/src/bot/routeReport.test.ts --silent=false
```

Бот проходит все проверенные seed каждого уровня как на полной кухне, так и на кухне каждого дня. Трудоёмкость блюд в `config/levels/dishes.ts` измерена на прежней кухне и не пересчитывалась: с короткими маршрутами терпения клиентов хватает с большим запасом.

## Сборка и запуск

### Режим разработки

```
npm run dev:cooking
```

Dev-сервер Vite стартует на порту 5174. Игра открывается по адресу `http://localhost:5174/?level=easy` (так же `medium` и `hard`). Без портала мост работает автономно: уровень берётся из адреса, старт приходит сразу. Перед запуском скрипт `predev:cooking` копирует `sdk/web/portal-bridge.js` в `games/cooking/public/`.

Для запуска из Claude Code есть конфигурация `cooking` в `.claude/launch.json` (корень репозитория). Встроенная панель браузера Claude Code блокирует запросы из изолированных фреймов, но обычная страница dev-сервера в ней открывается.

Страница разработчика `http://localhost:5174/harness.html` показывает сцену и HUD на готовом снимке без запуска смены. Параметры адреса: `?level=easy|medium|hard`, `?day=1..5` (день кампании: меню и мебель кухни этого дня, по умолчанию 5), `?phase=ready|running|failed`, `?elapsed=секунды`, `?mode=keyboard|touch`, `?fail=queue|table`, `?debug` (отладочный оверлей). Режим `?sim` запускает настоящую симуляцию с вашим вводом, режим `?bot&speed=3` запускает смену, в которой вместо игрока играет эталонный бот (в три раза быстрее).

### Сборка

```
npm run build:cooking
```

Сборка кладётся в `public/game-builds/cooking/`. Библиотека three.js выделена в чанк `vendor/`: папку `vendor/` не проверяют `check:dashes` и ESLint. Все пути в сборке относительные (`base: "./"`), внешних адресов нет, поэтому сборка работает и из изолированного фрейма портала. Скрипт `prebuild:cooking` так же копирует `portal-bridge.js`.

Результат сборки хранится в git, коммиты делает человек. Не коммитьте сборку, собранную с включённой отладкой (см. ниже).

### Проверка в портале

1. `npm run dev` и обычный браузер (не встроенная панель Claude Code).
2. Прямой адрес сборки: `http://localhost:3000/game-builds/cooking/index.html?level=easy`.
3. Поток портала: `/games`, карточка игры, "Начать", фрейм, результат, `/diplomas`. Уровень открывается и по адресу `/games/cooking/easy`.

### Отладка

Режим отладки включается одной переменной в файле `web/.env`:

```
NEXT_PUBLIC_DEBUG=true
```

В игре появляется оверлей с сеткой навигации, путями персонажей и точкой выбора цели повара, а модули пишут сообщения в консоль с меткой `[cooking:<область>]`. Для `dev:cooking` переменная читается на лету, для `build:cooking` значение зашивается в сборку при её создании.

## Как добавить блюдо

Новое блюдо затрагивает данные, а не логику: большая часть логики описана таблицами. Подсказка: многие места это `Record<DishId, ...>`, и TypeScript (`npm run typecheck`) сам покажет, где блюдо ещё не описано.

1. `contracts.ts`: добавьте идентификатор в `DISH_IDS`. Если нужен новый ингредиент или состояние, добавьте вид в `IngredientKind` и пары в `ITEM_CATALOG` (это перечень допустимых предметов, только они возникают в игре). Если нужен новый процесс готовки, добавьте его в `CookRecipeId`.
2. `sim/kitchen/recipes.ts`: рецепт в `dishRecipes` (набор ингредиентов на тарелке). Для новой резки добавьте строку в `cutTransitions`, для новой готовки (какая станция, что положить, что получится, что сгорит) строку в `cookTransitions`. Вид сырья, который выдаёт ящик, перечислен в `crateIngredientKinds`.
3. Баланс: цена, чаевые и трудоёмкость блюда в `config/levels/dishes.ts` (`calibratedDishes`, настоящие уровни) и в `config/levels/defaults.ts` (значения для тестов областей); время готовки и подгорания по процессам в `params.kitchen.cooking` (`defaults.ts`). Трудоёмкость (`effort`) не выдумывается, а измеряется ботом (раздел "Проверенные seed").
4. Уровни: добавьте блюдо в `params.menu` нужных уровней (`config/levels/easy.ts`, `medium.ts`, `hard.ts`) и поставьте ящики и станции, которые для него нужны. Тесты `config/levels/levels.test.ts` проверяют, что у меню есть ящики и станции.
5. Тексты: название блюда в `texts/hud.ts` (`dishNames`).
6. Модели (`config/assets.ts`): модель каждой пары предмета в `itemModelByKey`, модель готового блюда в `dishModelNames`, модель ящика в `crateModelNames`. Новые файлы glTF кладутся в `games/cooking/public/models/` и добавляются в `coreModelNames` (тест `config/assets.test.ts` проверяет, что все файлы из списка существуют).
7. Бот: если у блюда новый процесс готовки, он должен знать его (`COMPONENT_OF_DISH` и `COOKER_KIND_OF_COMPONENT` в `bot/bot.ts`). Иначе бот не пройдёт уровень с этим блюдом.
8. Тесты: `sim/kitchen/recipes.test.ts` проверяет, что для каждого блюда цепочка таблиц ведёт от ящиков к готовому блюду, сценарии кухни лежат в `sim/kitchen/index.test.ts`.
9. После смены меню или трудоёмкости пересоберите список проверенных seed (раздел ниже).

## Как добавить станцию

Ещё одна станция уже известного вида (доска, плита, прилавок, ящик) это одна строка в `stations` уровня:

```ts
station(3, "board-1", "cuttingBoard", 4, 3),    // день появления, id, вид, столбец 1..6 и ряд 1..5 клетки кухни
crate(5, "onion", 2, 1),                        // ящик с ингредиентом
```

Строки лежат в `createSharedKitchenStations` (`config/levels/sharedLayout.ts`), свободных клеток на кухне нет: новую станцию придётся ставить вместо другой или расширять кухню. Перед правкой расстановки сравните маршруты отчётом из раздела "Планировка кухни".

Правила: идентификатор уникален, станция 1 x 1 стоит на сетке 0.5 внутри границ мира и не пересекается с другой мебелью, к ней можно подойти. Проверка: `npx vitest run games/cooking/src/config` (`validateLevelConfig` и тесты достижимости обходят все цели по навигационной сетке из точки старта повара и из точек ожидания официантов). Затем пересоберите список seed: новая станция меняет время бота.

Станция нового вида:

1. `contracts.ts`: вид в `StationKind`.
2. `sim/kitchen/index.ts`: правила `interact` для вида (рука и станция, причины отказа `ActionRejectReason`), при необходимости `step` и снимок станции (`getStationSnapshots`); таблицы переходов в `sim/kitchen/recipes.ts`.
3. `config/assets.ts`: модель основания в `stationBaseModelNames` (тип `Record<StationKind, ...>`, TypeScript потребует запись), надстройки в `stationTopModelNames`; рисование и индикаторы прогресса в `render/stations.ts`.
4. `config/levels/validate.ts` и `config/levels/reachability.ts`: если станция должна быть достижимой цели, она попадает в обход целей автоматически по списку `stations`; особые правила (например, ровно одна станция) добавляются в `validateLevelConfig`.
5. `bot/bot.ts`: бот должен уметь пользоваться станцией, если без неё нельзя приготовить блюдо меню.
6. Тест на сценарий станции в `sim/kitchen/index.test.ts` и пересчёт seed.

## Параметры уровня

Один уровень это один файл данных: `config/levels/easy.ts`, `medium.ts`, `hard.ts` (раскладка кухни и зала, станции, столы, дверь, очередь, параметры). Параметры задаются вызовом `createParams({...})`: значения по умолчанию лежат в `config/levels/defaults.ts`, уровень переопределяет нужные (слияние глубокое, массивы заменяются целиком), цены и трудоёмкость блюд берутся из `config/levels/dishes.ts`. Тип параметров `LevelParams` с комментариями к каждому полю лежит в `contracts.ts`.

| Группа | Поля | Смысл |
| --- | --- | --- |
| Смена | `durationSec`, `menu` | длительность (180, 240, 300 с), блюда меню |
| Блюда | `dishes` | цена, максимальные чаевые, трудоёмкость |
| Расписание | `schedule.meanGapSec`, `minGapSec`, `firstArrivalSec`, `flowCloseBeforeEndSec`, `groupSizeWeights`, `workBudgetShare`, `workWindowSec`, `botCapacity` | поток клиентов и "бюджет работы": доля пропускной способности бота, которую может занять нагрузка в любом окне |
| Терпение | `patience.queueSec`, `tableBaseSec`, `tableEffortCoef`, `tableWaiterAllowanceSec` | очередь: фиксированное; за столом: база плюс коэффициент на трудоёмкость плюс запас на официанта |
| Клиенты | `customers.eatSec`, `seatingBypassSec`, `speed` | время еды, порог обхода крупной группы, скорость |
| Кухня | `kitchen.cutSec`, `cooking`, `potCapacity`, `stewPortionsPerBatch` | время резки, готовки и подгорания, кастрюля |
| Повар, навигация, официанты | `player`, `nav`, `waiter.capacity`, `speed`, `handoffSec` | скорости, радиусы, вместимость официанта (1 на easy и medium, 2 на hard) |

Что менять и что запускать:

1. Измените значение в файле уровня (число баланса не пишется в код симуляции: если нужного поля нет, добавьте его в `LevelParams` в `contracts.ts` и значение в `defaults.ts`).
2. Проверьте данные уровней: `npx vitest run games/cooking/src/config`.
3. Прогоните бота и обновите списки seed (следующие разделы). Спецификация требует, чтобы терпение не возрастало, а поток клиентов не убывал от easy к hard: это проверяет `levels.test.ts` (сценарий "Сравнение уровней").
4. Весь отображаемый текст правится только в `texts/`.

## Проверенные seed

Расписание дня строится из seed, а у каждого уровня есть список `verifiedSeeds` (поле в `config/levels/<уровень>.ts`). При запуске уровня игра берёт случайный seed из этого списка (`pickVerifiedSeed` в `config/levels/index.ts`), расписание непроверенного seed в игре не используется. Каждый seed из списка заранее прогнан эталонным ботом.

Seed подходит, если бот (`bot/verify.ts`, функция `verifySeed`):

- обслужил всех клиентов дня и закончил смену не позже чем за 10 секунд до конца таймера (`MIN_TIME_MARGIN_SEC`);
- ни разу не опустил терпение за столом и в очереди ниже 25 процентов (`MIN_PATIENCE_MARGIN`);
- не переполнил очередь (групп в очереди не больше слотов);
- не допустил, чтобы движущийся персонаж стоял без движения дольше 4 секунд (`STUCK_THRESHOLD_SEC`).

Для списка дополнительно требуется, чтобы расписание содержало все блюда меню и не меньше 6, 9 и 14 клиентов на easy, medium и hard (`MIN_SCHEDULE_CUSTOMERS`). Невыполнимый seed в список не попадает.

### Как обновить список

После смены параметров уровня, меню, раскладки или трудоёмкости блюд:

```
COOKING_SEED_SEARCH=1 npx vitest run games/cooking/src/bot/seedSearch.test.ts
```

В PowerShell переменная задаётся отдельной командой:

```
$env:COOKING_SEED_SEARCH=1; npx vitest run games/cooking/src/bot/seedSearch.test.ts
```

Без переменной этот тест пропускается, поэтому обычный прогон тестов не тратит на него время. Поиск идёт около двух минут: бот проходит по 120 кандидатов на каждый уровень. Результат печатается в консоль и пишется в файл `cooking-seed-search.json` во временной папке системы (`os.tmpdir()`), для каждого уровня там два поля:

- `verifiedSeeds`: копируйте в поле `verifiedSeeds` файла `config/levels/<уровень>.ts`;
- `busyPerDish`: секунды работы бота на блюдо без ожидания готовности (считается отдельно по каждому уровню, где блюдо есть в меню). Это измеренная трудоёмкость: в `config/levels/dishes.ts` у блюда одно значение `effort` на все уровни, поэтому берите среднее по уровням, округлённое до целого. После смены `effort` список seed подбирается заново (расписание зависит от трудоёмкости), поэтому поиск выполняется ещё раз, пока значения не перестанут меняться.

После переноса запустите тесты бота и уровней (следующий раздел): они подтвердят каждый seed из списка.

## Тесты бота и уровней

Эталонный бот (`bot/bot.ts`, функции `createBot` и `runBot`) проходит смену в симуляции без рендера: жадный планировщик, ходит по A*, пользуется только публичным снимком симуляции. Он даёт нижнюю оценку времени и доказывает, что уровень проходим.

Тесты бота и данных уровней (около 30 секунд):

```
npx vitest run games/cooking/src/bot games/cooking/src/config
```

- `bot/bot.test.ts`: бот проходит тестовый мини-уровень с `completed = true`, готовит все четыре блюда, воспроизводим по seed;
- `bot/levelsBot.test.ts`: достижимость целей по навигационной сетке, бот проходит каждый проверенный seed каждого уровня (очередь не переполняется, терпение не истекает), отсутствие дедлоков, выбор seed, невыполнимый seed отбрасывается;
- `config/levels/levels.test.ts` и `validate.test.ts`: структура уровней, станции под меню, модели из списка ассетов, сравнение уровней между собой.

Сквозные тесты симуляции с ботом на easy, medium и hard:

```
npx vitest run games/cooking/src/sim/simulation.test.ts
```

Все тесты игры одной командой (около минуты, из них тесты бота полминуты):

```
npx vitest run games/cooking
```

Перед коммитом выполняется полная проверка проекта: `npm run check` (типы, тесты, тире, линтер). Проверка тире отдельно: `npm run check:dashes`. В тестах симуляции первой строкой стоит `// @vitest-environment node`, остальные тесты выполняются в jsdom (общий конфиг).
