# Протокол моста портал - игра (версия 1)

Протокол нужен играм, которые подключаются готовой веб-сборкой (Unity WebGL, three.js, любая HTML5-игра), см. `docs/adding-game.md`. Обычно напрямую с ним работать не нужно: SDK из `sdk/` отправляет и принимает сообщения сам. Документ пригодится, если игра пишет мост сама или нужно отладить обмен.

Константы протокола на стороне портала: `core/bridge/protocol.ts`. На стороне игры: `sdk/web/portal-bridge.js`.

## Запуск

1. Портал открывает стартовую страницу сборки во фрейме: `runtime.entry?level=<levelId>`, например `/game-builds/city-builder/index.html?level=easy`.
2. Фрейм изолирован: `sandbox="allow-scripts"` без `allow-same-origin`. У игры непрозрачный источник `null`: нет доступа к LocalStorage, IndexedDB, cookie и странице портала.
3. Игра загружается и отправляет `ready`.
4. Портал отвечает `start` с идентификаторами игры и уровня, сохранённым блоком `progress` или `null`, и передаёт фокус фрейму.
5. Игра может сохранять блок `progress`, затем отправляет `level-result`, `exit` или `error`.

## Сообщения

Каждое сообщение - объект с полями `source`, `version` и `type`. Сообщения без метки, с другой версией или неизвестным типом портал игнорирует (при `NEXT_PUBLIC_DEBUG=true` пишет их в консоль).

### Игра -> портал (`source: "portal-game"`)

```json
{ "source": "portal-game", "version": 1, "type": "ready" }
```
Игра готова принять уровень. Отправляется один раз после загрузки.

```json
{ "source": "portal-game", "version": 1, "type": "progress", "data": { "version": 1, "items": [] } }
```

Блок игры: JSON-объект размером не больше 4096 байт UTF-8. Портал принимает его только от iframe текущей попытки после `ready`, хранит отдельно для каждого `gameId` и передаёт в следующем `start`. Игра должна считать блок недоверенным и проверять его структуру. Команда «Сбросить результаты» удаляет блоки прогресса вместе с результатами.

```json
{ "source": "portal-game", "version": 1, "type": "level-result", "score": 8, "maxScore": 10, "completed": true }
```
Итог уровня. `score` и `maxScore` - числа, `0 <= score <= maxScore`, `maxScore > 0`. `completed: false`, если игрок бросил уровень, но очки нужно сохранить: попытка сохранится без наград. Принимается один результат за запуск. `gameId`, `levelId` и время уровня портал берёт из запуска, а не из сообщения.

Свободный режим БПЛА запускается с `mode=free`. На этом маршруте завершённое упражнение отправляет отдельный итог для PDF.

```json
{ "source": "portal-game", "version": 1, "type": "practice-result", "activity": "race", "difficulty": null, "score": 92, "completed": true, "durationSec": 36 }
```

`activity` принимает `assembly`, `survey`, `beach`, `field` или `race`. Для сборки и фоторазбора `difficulty` содержит один из идентификаторов сложности, для полётов содержит `null`. Баллы свободного упражнения не влияют на сюжетный прогресс.

```json
{ "source": "portal-game", "version": 1, "type": "exit" }
```
Игрок вышел из игры без результата. Портал показывает экран "Уровень не завершен" и ничего не сохраняет.

```json
{ "source": "portal-game", "version": 1, "type": "error", "message": "WebGL недоступен" }
```
Игра не может продолжать. Портал показывает запасной экран с повтором. Текст ошибки виден только в консоли в режиме отладки.

### Портал -> игра (`source: "portal"`)

```json
{ "source": "portal", "version": 1, "type": "start", "gameId": "city-builder", "levelId": "easy", "progress": null }
```
Уровень можно начинать. Приходит только после `ready`. Старые игры могут игнорировать `progress`; старые версии портала не отправляют его.

Для БПЛА родитель может передавать стандартные оси и кнопки геймпада отдельным сообщением `{ source: "portal", type: "gamepad", sample: { axes, buttons } }`. В `axes` четыре оси стандартной раскладки, в `buttons` пять состояний A, B, X, Y и Menu. `sample: null` сбрасывает состояние переданного контроллера.

## Состояния уровня на стороне портала

```
   loading --ready--> running --level-result--> finished (экран итога)
      |                  |------exit---------> abandoned (экран "не завершён")
      |                  |------error--------> failed (запасной экран)
      +--timeout/error-------------------------> failed
   кнопка выхода портала из любого состояния --> библиотека игр
```

- Таймаут `loading`: `runtime.readyTimeoutSec` из манифеста, по умолчанию 30 секунд.
- Сообщения, которые не подходят текущему состоянию (например, второй `level-result`), игнорируются.
- Сообщения принимаются только от фрейма текущего уровня (`event.source`). Проверять `event.origin` бесполезно: у изолированного фрейма он всегда `"null"`.

## Раздача файлов сборки

Для `/game-builds/*` портал отдаёт заголовки:

- `Access-Control-Allow-Origin: *` - иначе изолированный фрейм не загрузит модули, `.wasm` и `.data`;
- `Content-Security-Policy: sandbox allow-scripts` - сборка остаётся изолированной, даже если открыть её прямо по адресу.

Сборка БПЛА также разрешает открывать карточки производителей в отдельной вкладке. Сам фрейм сохраняет непрозрачный источник.
