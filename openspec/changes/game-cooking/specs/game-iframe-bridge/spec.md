# Spec Delta

## MODIFIED Requirements

### Requirement: Level launch handshake
Портал SHALL открыть стартовую страницу сборки во фрейме, передав идентификатор уровня в адресе, и после сообщения игры о готовности отправить ей сообщение о старте с идентификаторами игры и уровня и сохранённым блоком данных игры, если он есть.

#### Scenario: Game receives the level after it is ready
- **WHEN** сборка загрузилась и отправила сообщение о готовности
- **THEN** портал отправляет ей сообщение о старте с `gameId` и `levelId` выбранного уровня

#### Scenario: Start is not sent before ready
- **WHEN** сборка ещё не отправила сообщение о готовности
- **THEN** портал не отправляет сообщение о старте и показывает индикатор загрузки

#### Scenario: Start carries the saved game data
- **WHEN** для запущенной игры в LocalStorage портала лежит блок данных игры
- **THEN** сообщение о старте содержит этот блок в поле `progress`

#### Scenario: Start without saved game data
- **WHEN** блока данных игры нет или LocalStorage недоступен
- **THEN** сообщение о старте содержит `progress` равным `null`, а старая игра, не знающая этого поля, работает как раньше

### Requirement: Web game SDK
Для веб-игр SHALL предоставляться готовый скрипт моста, через который игра получает уровень и блок данных игры из старта, отправляет результат, выход или обновлённый блок данных одним вызовом, не зная формата сообщений.

#### Scenario: three.js game finishes a level through the SDK
- **WHEN** игра на three.js подключает скрипт моста, получает уровень через него и вызывает отправку результата
- **THEN** портал получает сообщения о готовности и результате в правильном формате

#### Scenario: Game reads and saves data through the SDK
- **WHEN** игра в обработчике старта читает блок данных и вызывает сохранение нового блока
- **THEN** портал получает сообщение с блоком, а при следующем старте игра получает сохранённый блок

#### Scenario: Oversized data is refused before sending
- **WHEN** игра вызывает сохранение блока размером больше 4096 байт
- **THEN** вызов возвращает отказ и сообщение порталу не отправляется

### Requirement: Unity SDK
Для Unity SHALL предоставляться плагин и обёртка на C# с теми же действиями, что у веб-SDK (в том числе чтение и сохранение блока данных игры), и шаблон WebGL-страницы, который подключает мост.

#### Scenario: Unity game reports a result from C#
- **WHEN** Unity-игра, собранная с шаблоном портала, вызывает из C# отправку результата
- **THEN** портал получает сообщение о результате в правильном формате

#### Scenario: Unity game saves data from C#
- **WHEN** Unity-игра вызывает из C# сохранение блока данных в виде JSON
- **THEN** портал получает сообщение с блоком в правильном формате

## ADDED Requirements

### Requirement: Game data block
Портал SHALL принимать от запущенной игры сообщение с блоком данных игры (JSON-объект не больше 4096 байт), хранить его в LocalStorage по идентификатору игры и отдавать игре при следующем старте. Блок MUST заменяться целиком. Сообщение MUST приниматься только от фрейма запущенного уровня и только после старта; блок, не являющийся объектом, не сериализуемый или больше лимита, MUST отбрасываться без ошибки для игры и без изменения сохранённого блока. Блок MUST NOT влиять на результат уровня.

#### Scenario: Data block is stored
- **WHEN** запущенная игра отправляет блок данных `{ "version": 1, "cookedDishes": ["burger"] }`
- **THEN** портал сохраняет его для этой игры, и при следующем запуске любого уровня игра получает его в старте

#### Scenario: Oversized block is dropped
- **WHEN** игра отправляет блок больше 4096 байт
- **THEN** сохранённый блок не меняется

#### Scenario: Non-object block is dropped
- **WHEN** игра отправляет вместо объекта строку, число или массив
- **THEN** сохранённый блок не меняется

#### Scenario: Data message before start is ignored
- **WHEN** сборка отправляет блок данных до сообщения о старте
- **THEN** портал его игнорирует

#### Scenario: Data message from another window is ignored
- **WHEN** сообщение с блоком приходит не из фрейма запущенного уровня
- **THEN** портал его игнорирует

#### Scenario: Old portal ignores the data message
- **WHEN** игра с новым SDK отправляет блок данных порталу, который такого сообщения не знает
- **THEN** портал игнорирует сообщение как неизвестное, уровень идёт и завершается как обычно

#### Scenario: Old game ignores the data field
- **WHEN** старт с блоком данных приходит в игру со старым SDK
- **THEN** игра игнорирует лишнее поле и запускается как раньше

#### Scenario: Storage is unavailable
- **WHEN** LocalStorage недоступен
- **THEN** блок хранится в памяти текущей сессии портала, а старт без сохранённого блока содержит `progress` равным `null`, не останавливая уровень
