# Spec Delta

## Purpose

Подключение к порталу отдельно собранных веб-игр (Unity WebGL, three.js, любая HTML5-игра) без React-кода: сборка открывается в изолированном фрейме и обменивается с порталом сообщениями по версионируемому протоколу.

## ADDED Requirements

### Requirement: Build declared in manifest
Игра SHALL иметь возможность объявить в манифесте сборку вместо компонентов уровней: вид запуска `iframe` и путь к стартовой странице сборки внутри папки `/game-builds/<gameId>/`. Манифест с другим видом запуска, пустым путём или путём вне папки своей игры MUST отклоняться при регистрации.

#### Scenario: Iframe game is registered without level components
- **WHEN** манифест объявляет вид запуска `iframe` и путь `/game-builds/<gameId>/index.html`, а компонентов уровней у игры нет
- **THEN** игра регистрируется и появляется в библиотеке игр с тремя уровнями

#### Scenario: Build path outside the game folder is rejected
- **WHEN** путь к сборке указывает за пределы `/game-builds/<gameId>/` или на внешний адрес
- **THEN** игра не регистрируется и в журнал пишется причина

### Requirement: React games keep working
Игра без объявленной сборки SHALL запускаться через свои компоненты уровней, как до появления моста.

#### Scenario: Game without runtime uses its component
- **WHEN** пользователь открывает уровень игры, в манифесте которой нет вида запуска
- **THEN** портал показывает компонент уровня этой игры

### Requirement: Level launch handshake
Портал SHALL открыть стартовую страницу сборки во фрейме, передав идентификатор уровня в адресе, и после сообщения игры о готовности отправить ей сообщение о старте с идентификаторами игры и уровня.

#### Scenario: Game receives the level after it is ready
- **WHEN** сборка загрузилась и отправила сообщение о готовности
- **THEN** портал отправляет ей сообщение о старте с `gameId` и `levelId` выбранного уровня

#### Scenario: Start is not sent before ready
- **WHEN** сборка ещё не отправила сообщение о готовности
- **THEN** портал не отправляет сообщение о старте и показывает индикатор загрузки

### Requirement: Versioned message format
Каждое сообщение моста SHALL содержать метку протокола и номер версии. Портал MUST игнорировать сообщения без метки, с неизвестной версией или неизвестным типом, а при включённом режиме отладки писать их в журнал.

#### Scenario: Message with unknown version is ignored
- **WHEN** игра отправляет сообщение с версией протокола, которую портал не поддерживает
- **THEN** портал не меняет состояние уровня и не сохраняет результат

### Requirement: Messages accepted only from the level frame
Портал SHALL принимать сообщения моста только от фрейма запущенного уровня.

#### Scenario: Message from another window is ignored
- **WHEN** сообщение в правильном формате приходит не из фрейма уровня, например из другой вкладки или вложенного окна
- **THEN** портал его игнорирует

### Requirement: Game isolated from portal data
Сборка игры SHALL выполняться в изоляции от портала: она MUST NOT иметь доступа к LocalStorage, cookie и странице портала.

#### Scenario: Game cannot read portal storage
- **WHEN** код игры пытается прочитать данные портала из LocalStorage
- **THEN** данные портала ему недоступны, а результаты, ачивки и дипломы пользователя не меняются

### Requirement: Build assets load in the isolated frame
Файлы сборки из `/game-builds/` SHALL загружаться в изолированном фрейме, включая модули JavaScript, WebAssembly и файлы данных Unity.

#### Scenario: Unity and module builds load
- **WHEN** изолированный фрейм запрашивает файлы `.js`, `.wasm` и `.data` своей сборки
- **THEN** файлы загружаются без ошибок доступа между источниками

### Requirement: Level result from the game
По сообщению игры с результатом портал SHALL сохранить попытку с очками, максимумом очков и признаком завершения из сообщения, а `gameId`, `levelId` и время уровня MUST брать из запуска, а не из сообщения.

#### Scenario: Completed level is recorded with platform timing
- **WHEN** игра отправляет результат с `score=8`, `maxScore=10`, `completed=true` через 95 секунд после старта
- **THEN** портал сохраняет попытку запущенной игры и уровня с `durationSec=95` и показывает экран итога уровня

#### Scenario: Message cannot change game or level
- **WHEN** сообщение с результатом содержит другие `gameId` или `levelId`
- **THEN** портал использует идентификаторы запущенного уровня

### Requirement: One result per launch
Портал SHALL принять не больше одного результата за запуск уровня.

#### Scenario: Repeated result is ignored
- **WHEN** игра отправляет второй результат после первого
- **THEN** второй результат не сохраняется и не даёт наград

### Requirement: Exit without result
Если игра сообщила о выходе до отправки результата, портал SHALL показать экран незавершённого уровня с кнопками повтора и возврата в библиотеку и MUST NOT сохранять попытку.

#### Scenario: Player leaves the game
- **WHEN** игра отправляет сообщение о выходе, не отправив результат
- **THEN** портал показывает экран незавершённого уровня, а список попыток не меняется

### Requirement: Platform exit control
Портал SHALL показывать рядом с фреймом собственную кнопку выхода из уровня, которая работает независимо от состояния игры и не сохраняет попытку.

#### Scenario: Exit from a frozen game
- **WHEN** игра зависла и не отвечает, а пользователь нажимает кнопку выхода портала
- **THEN** уровень закрывается, пользователь возвращается в библиотеку игр, попытка не сохраняется

### Requirement: Load timeout
Если игра не сообщила о готовности за время ожидания, портал SHALL показать запасной экран уровня. Время ожидания по умолчанию 30 секунд, игра MAY задать своё в манифесте.

#### Scenario: Game does not become ready
- **WHEN** за время ожидания от сборки не пришло сообщение о готовности
- **THEN** портал показывает запасной экран с повтором и возвратом в библиотеку

### Requirement: Game error report
По сообщению игры об ошибке портал SHALL показать запасной экран уровня.

#### Scenario: Game reports a fatal error
- **WHEN** игра отправляет сообщение об ошибке, например не удалось инициализировать WebGL
- **THEN** портал показывает запасной экран, а текст ошибки пишет в журнал только в режиме отладки

### Requirement: Keyboard focus on start
После отправки сообщения о старте портал SHALL передать фокус фрейму игры, чтобы управление с клавиатуры работало без дополнительного клика.

#### Scenario: Keyboard works right after start
- **WHEN** уровень стартовал
- **THEN** нажатия клавиш попадают в игру

### Requirement: Web game SDK
Для веб-игр SHALL предоставляться готовый скрипт моста, через который игра получает уровень и отправляет результат или выход одним вызовом, не зная формата сообщений.

#### Scenario: three.js game finishes a level through the SDK
- **WHEN** игра на three.js подключает скрипт моста, получает уровень через него и вызывает отправку результата
- **THEN** портал получает сообщения о готовности и результате в правильном формате

### Requirement: Unity SDK
Для Unity SHALL предоставляться плагин и обёртка на C# с теми же действиями, что у веб-SDK, и шаблон WebGL-страницы, который подключает мост.

#### Scenario: Unity game reports a result from C#
- **WHEN** Unity-игра, собранная с шаблоном портала, вызывает из C# отправку результата
- **THEN** портал получает сообщение о результате в правильном формате
