# Design

## Context

- Мотивация и состав игры: см. proposal.md.
- React-игра подключается модулем `games/<gameId>` с `levelComponents`. `LevelRunner` передаёт компоненту уровня `{ level, onFinish }` и сохраняет результат; игра не пишет в LocalStorage сама.
- В портале два способа подключения: React-модуль (`games/demo`) и сборка во фрейме через мост (`games/city-builder`, `sdk/web`, `sdk/unity`). Встроенная панель браузера Claude Code блокирует изолированные фреймы, React-игры в ней проверяются напрямую.
- Зависимости портала: только `next` и `react`. Цвета и радиусы портала заданы переменными в `web/app/globals.css`, светлая и тёмная тема переключаются через `prefers-color-scheme`.
- Список профессий существует только в `web/texts/professions/index.ts`, в спецификациях его нет.

## Goals / Non-Goals

**Goals:**
- Каждую мини-игру можно разработать, протестировать и заменить отдельно от уровня.
- Очки считаются чистыми функциями, которые покрываются тестами без отрисовки.
- Любую мини-игру можно пройти мышью, касанием и с клавиатуры.
- Интерфейс узнаётся как учётная программа, но не копирует интерфейс 1С.

**Non-Goals:**
- Случайная генерация заданий: данные уровней фиксированы, перемешивается только порядок.
- Сохранение прогресса внутри уровня при перезагрузке страницы.
- Дилемма директора на уровне hard (письмо «оплатить без договора»): в этот change не входит, может быть добавлена позже отдельным требованием.

## Decisions

### D1. React-модуль, а не сборка во фрейме

Игра подключается как `games/accountant-1c` с одним компонентом уровня на все три уровня.

- **Почему:** все мини-игры это таблицы, формы, поля ввода и списки, то есть обычный HTML. React-модуль получает тексты в `texts/`, тесты через vitest, проверку `npm run check` и проверку во встроенном браузере.
- **Отклонено:** сборка на чистом JS во фрейме через `sdk/web/portal-bridge.js` (нет тестов vitest, тексты вне проверки тире, нельзя проверить во встроенном браузере; нужна только для отдельной команды со своим стеком); Unity WebGL (тяжёлая сборка для табличной игры, Unity-часть SDK не проверена).

### D2. Уровень как сценарий из фаз, мини-игры описаны данными

`AccountantLevel` проходит фазы: письмо-вступление, мини-игра A, сцена с итогом A, мини-игра B, экран «Закрытие месяца». Какие мини-игры и с какими данными идут в уровне, описано в `data/levels.ts`:

```
easy:   [ documentSorting(easyDocuments), cashDesk(easyCash) ]
medium: [ postings(mediumOperations),     payroll(mediumStaff) ]
hard:   [ bankReconciliation(hardStatement), balanceSheet(hardBalance) ]
```

- **Почему:** один компонент уровня вместо трёх; смена или перестановка мини-игры меняет только данные; сценарий проверяется одним тестом для всех уровней.
- **Отклонено:** отдельный компонент на каждый уровень (дублирование фаз, итога и выхода); одна мини-игра на уровень (меньше разнообразия, решено с пользователем).

### D3. Единый интерфейс мини-игры и шкала 10 очков

Каждая мини-игра получает свои данные и `onComplete(outcome)`, где `outcome` содержит очки от 0 до 10 и список ошибок с идентификаторами объяснений. Очки считает чистая функция мини-игры в `scoring.ts`:

- первичка, проводки, зарплата: `round(10 * верных / всего)`;
- касса: по 1 очку за документ и сумму каждого посетителя, 2 за сдачу излишка в банк;
- сверка: 1,5 за найденное расхождение, 1 за верную причину, минус 1 за ложную отметку, не ниже 0;
- баланс: 1 за каждую статью с известной суммой, 2 за вычисленную нераспределённую прибыль;
- подсказка на medium: минус 1, не ниже 0.

Уровень складывает очки двух мини-игр, `maxScore = 20`.

- **Почему:** одинаковый вес мини-игр делает доли сравнимыми между уровнями; разные мини-игры с разным числом проверок не перевешивают друг друга.
- **Отклонено:** сырые очки (зарплата из 10 полей перевешивала бы кассу); дробная шкала доли без округления (неудобно показывать игроку).

### D4. Данные отдельно от текстов, перемешивание с внедряемым генератором

Числа, счета, идентификаторы документов и правильные ответы лежат в `data/levels.ts`, все строки (названия документов, реплики, письма, подписи кнопок) лежат в `texts/index.ts` и связаны с данными по идентификаторам. Порядок карточек перемешивает функция `shuffle(items, random)`, где `random` по умолчанию `Math.random`, а в тестах передаётся детерминированный.

- **Почему:** соблюдается правило «весь отображаемый текст в отдельных файлах»; тесты не зависят от случайности.
- **Отклонено:** тексты прямо в данных (нарушает CodeStyle.md); фиксированный порядок (перепрохождение становится запоминанием).

### D5. Окно учётной программы в жёлто-красной гамме на рабочем столе

Игра рисует окно «Учёт: ООО Ромашка»: панель разделов, вкладки форм, журналы с отметкой проведения, формы с кнопками «Провести и закрыть», «Записать», «Провести», «Дт/Кт», панель «Сообщения», уведомления в углу, панель «Обсуждения» для главбуха. Палитра окна жёлто-красная, как привычно для учётных программ этого жанра, задаётся локальными переменными в CSS-модуле игры и всегда светлая.

Окно стоит на рабочем столе в духе игр про проверку документов: тёмный стол, окошко кассы с персонажем, бумажные документы с тенью и лёгким наклоном, резиновый штамп, настольный калькулятор, часы рабочего дня. Стол рисуется своей графикой и не зависит от темы портала.

- **Почему:** решено с пользователем 20.11.2026: игра должна ощущаться как игра, а не как форма; жёлто-красная гамма сразу узнаётся как учётная программа.
- **Граница:** нет логотипа, названия и иконок 1С, нет копии заставки и точной раскладки окон; от игр про проверку документов берётся только жанр (стол, бумаги, штамп), без чужой графики, персонажей, шрифтов и раскладки экрана.
- **Отклонено:** точная копия интерфейса 1С (риск по товарному знаку и фирменному стилю); копия экрана конкретной игры про проверку документов.

### D11. Настольный калькулятор и штамп

На столе лежит калькулятор: кнопки мышью и касанием, ввод с клавиатуры, лента с историей, клавиша «%» и кнопка «В поле», которая вставляет результат в последнее выбранное поле суммы. Кнопки проведения документа работают как резиновый штамп: на бумаге остаётся красный оттиск «ПРОВЕДЕНО». Калькулятор и штамп не влияют на очки.

- **Почему:** расчёты НДФЛ, излишка кассы и прибыли делаются прямо в игре, без внешнего калькулятора; штамп даёт ощущение действия.

Дополнено по решению пользователя 20.11.2026 («игра, а не html-форма»): рабочее место устроено как настольная игра про проверку документов.

- **Раскладка своя:** вверху слева окошко в коридор с пиксельным персонажем и его репликой, справа от него окно программы (монитор), под ними во всю ширину стол. Часы рабочего дня идут от 09:00 и ни на что не влияют.
- **Бумаги на столе** перетаскиваются куда угодно и поднимаются наверх стопки; бумага, брошенная на цель (штамп, строку баланса, строку учёта), обрабатывается как выбор цели (D6). Ввод «выбрать, затем цель» и клавиатура сохраняются.
- **Задания перенесены на стол:** первичка раскладывается штампами разделов; в кассе бланк ПКО или РКО отрывается от блока, заполняется и отдаётся в окошко; в проводках на столе лежат первичные документы, проводка вводится в программе; в зарплате число детей видно только в заявлениях на вычет на столе; выписка и карточка счёта 51 лежат на столе двумя листами; ОСВ лежит карточками рядом с бланком баланса.
- **Справочник** (папка с вкладками: план счетов, НДФЛ и вычеты, касса, сверка, баланс) открывается на столе.
- **Замечания:** ошибка печатает на столе листок «Замечание» от главбуха (правильный ответ, причина, шутка), листок можно убрать.
- **Утро и вечер:** день начинается газетой «Вестник ООО Ромашка» и письмом, заканчивается листом «Итоги дня» со штампом.
- **Шрифты:** пиксельный Pixelify Sans для заголовков и PT Mono для бумаг подключаются через `next/font` и раздаются самим сайтом, внешних запросов нет. В тестах `next/font/google` подменяется заглушкой через псевдоним в `vitest.config.mts`.
- **Граница остаётся из D5:** персонажи, графика, шрифты и раскладка свои.

### D6. Перетаскивание на Pointer Events плюс ввод без перетаскивания

Хук `useDrag` на Pointer Events перетаскивает документы, счета и статьи баланса; на перетаскиваемых элементах `touch-action: none`. Параллельно действует ввод «выбрать элемент, затем цель» нажатием и с клавиатуры (Tab, Enter, стрелки).

- **Почему:** HTML5 drag and drop не работает на сенсорных экранах; ввод без перетаскивания нужен для доступности и узких экранов.
- **Отклонено:** библиотека перетаскивания (новая зависимость ради нескольких сценариев).

### D7. Анимации на CSS и Web Animations API, иллюстрации inline SVG

Подъём документа, возврат при ошибке, штамп, счётчик сумм, наклон весов и состояния фикуса делаются на CSS-переходах и `element.animate`. При `prefers-reduced-motion: reduce` полёт и тряска заменяются появлением. Персонажи, фикус, печати, купюры и весы рисуются inline SVG и перекрашиваются переменными. Звука нет.

- **Отклонено:** библиотека анимаций (зависимость); растровые картинки (размытие на плотных экранах, нет перекраски).

### D8. Состояние фикуса и итог уровня выводятся из точности

Фикус показывает долю набранных очков от максимума уже пройденных проверок уровня: от 80% цветёт, от 50% растёт, от 25% поник, ниже засох. Экран «Закрытие месяца» использует те же пороги для штампа: от 80% «Проверено. Замечаний нет», от 50% «Принято с замечаниями», ниже «Требование ФНС». На очки ни фикус, ни штамп не влияют.

### D9. Один вызов `onFinish` за запуск

Компонент уровня держит флаг отправки результата. «Сдать отчёт» отправляет `completed: true` с суммой очков, «Уйти домой пораньше» в любой фазе отправляет `completed: false` с очками пройденных мини-игр; после отправки кнопки неактивны. Время уровня считается от монтирования компонента, как в `games/demo`.

### D10. Суммы в рублях целыми числами

Суммы в данных хранятся в рублях целыми числами, поскольку в игре нет копеек: НДФЛ округляется до полного рубля по правилу «меньше 50 копеек отбрасывается, 50 и больше до рубля». Ввод игрока разбирается с пробелами и запятой, отображение через `Intl.NumberFormat("ru-RU")`.

## Risks / Trade-offs

- [Изменились ставки НДФЛ, вычеты или правила кассы] → нормативные значения вынесены константами в `data/levels.ts` с комментарием-источником; перед реализацией и при каждом обновлении игры их сверяют.
- [Интерфейс сочтут копией 1С] → границы из D5; название профессии «Бухгалтер 1С» только на витрине; при сомнении приоритет у отличий.
- [Плотные таблицы плохо читаются на телефоне] → панель разделов сворачивается в верхнее меню, табличные части прокручиваются по горизонтали, «Сообщения» выезжают шторкой; проверка на ширине 375px во встроенном браузере.
- [Перетаскивание конфликтует с прокруткой на телефоне] → `touch-action: none` только на перетаскиваемых элементах, ввод нажатием всегда доступен.
- [Уровень дольше 5 минут] → объём данных подобран на 2-3 минуты на мини-игру; при проверке время уровня замеряется и при необходимости данные сокращаются.
- [Юмор мешает обучению] → каждая реплика об ошибке содержит правильный ответ и причину, шутка идёт второй фразой.

## Migration Plan

Новая игра и одна запись профессии; данных пользователей это не касается. Откат: убрать строку игры из `core/registry/index.ts`. Сохранённые результаты игры останутся в LocalStorage и не будут показываться, как у любой незарегистрированной игры.

## Open Questions

- Название игры «Закрытие квартала» и тексты реплик окончательно утверждаются при вычитке `texts/index.ts`; на требования и задачи это не влияет.
