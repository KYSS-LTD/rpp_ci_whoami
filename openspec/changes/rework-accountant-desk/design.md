# Design

## Context

Текущий Workplace собирает стол, окно программы и инструменты. Мини-игры владеют ответами и передают итоги уровню. Зависимости и границы описаны в proposal.md.

## Goals / Non-Goals

- Один источник состояния для каждой задачи и журнала.
- Доступность рабочих действий без жеста перетаскивания.
- Состояние смены остаётся частью запуска уровня.

## Decisions

1. **Бумаги и инструменты.** Рабочая зона E1 показывает один раскрытый лист рядом со стопкой. Локальные координаты оттиска задаются относительно листа, чтобы привязка сохранялась после перетаскивания, поворота и изменения размера. Такой якорь подходит для сохранения оттиска при адаптивной раскладке.
2. **Последовательные формы medium.** В M1 счёт из существующего плана представлен карточкой с кодом и названием. Бланк с двумя местами для карточек сохраняет решение о Дт и Кт. В M2 расчётный лист показывает исходные данные и одно поле, чтобы один ввод соответствовал одной проверке. Формула и округление НДФЛ остаются общими с текущими расчётами.
3. **Контекст отметки.** Выбранная в книге причина определяет допустимые виды полей, а идентификатор строки остаётся ключом проверки. Хранить вместе поле и причину, а запись в журнале вычислять из тех же данных. Существующий подсчёт получает проекцию отметок по строкам. Сопоставление строк и отметка полей используют отдельные режимы ввода.
4. **Один журнал в двух размерах.** Состояние журнала находится выше представлений окна. Разворот открывает доступную панель с возвратом фокуса к кнопке. При узкой ширине зоны занимают отдельные строки, прокрутка длинных таблиц ограничена таблицей.
5. **Обучение использует события заданий.** Шаги двигаются после действий на реальных контролах. Учебная проверка выполняется перед записью ответа, подсчётом и уведомлением об ошибке. При Esc первым закрывается выбранный инструмент, затем открытая панель, затем учебный слой. Кнопка пропуска доступна напрямую.

## Risks / Trade-offs

- Допустимые поля могут выдать ответ, если вычислять их по правильности. Фильтр использует только вид поля, проверка использует исходные данные.
- Журнал и бумага могут разойтись при редактировании. Обе поверхности используют одну запись отметки.
- При переходе между бумагами на 375 px может потеряться выбор инструмента. Выбор хранится на уровне мини-игры, а возврат восстанавливает рабочий контекст.
