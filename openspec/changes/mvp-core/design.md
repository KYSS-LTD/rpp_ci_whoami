# Design

## Context

Проект - клиентский сайт без серверной части для пользователей: все данные (имя, прохождение, ачивки, дипломы, оценки) живут в LocalStorage браузера. Мотивация и границы описаны в proposal.md, требования - в specs/. Игры разрабатываются параллельно разными командами, поэтому ядро должно давать им стабильный контракт.

Стек из config.yaml: Next.js (TypeScript) для фронтенда. FastAPI и PostgreSQL в этот change не входят, но архитектура должна оставлять для них место (статистика в админке).

## Goals / Non-Goals

**Goals:**
- Игра подключается без правок ядра: папка игры плюс строка в реестре.
- Единый слой хранения, через который проходят все чтения и записи LocalStorage.
- Логика ачивок, дипломов и анализа профессий - чистые функции без обращения к браузеру, легко тестируются.
- Отображаемый текст вынесен из кода.

**Non-Goals:**
- Серверная часть, учётные записи, верификация результатов на сервере.
- Сама реализация игр и их визуал.
- Генерация PDF-сертификатов сверх файла для сохранения (выбор формата - см. Decisions).

## Decisions

### D1. Структура проекта: монорепо с модулем ядра и папками игр

```
web/
  app/                  маршруты Next.js (/, /games, /games/[gameId]/[level], /me, /diplomas, /achievements)
  core/
    contract/           типы манифеста и результата игры, валидация манифеста
    registry/           реестр игр (список импортов игр)
    storage/            единый модуль LocalStorage с обёрткой try/catch
    achievements/       правила выдачи ачивок (чистые функции)
    diplomas/           выдача дипломов, расчёт рейтинга
    analysis/           расчёт баллов профессий (чистая функция)
    texts/              файлы текстов ядра
  games/
    <gameId>/
      manifest.ts       манифест игры
      levels/           компоненты трёх уровней
      texts/            тексты игры
      index.ts          экспорт в реестр
```

- Альтернатива: каждая игра как отдельный npm-пакет. Отвергнуто: лишний уровень сборки для команд, которым нужна только папка с файлами.
- Альтернатива: игры подгружаются динамически по имени из базы. Отвергнуто: данные игр не должны требовать сервера.

### D2. Реестр игр - явный список импортов

`core/registry` содержит один файл со списком импортов всех игр. Добавление игры - одна строка импорта и одна строка в списке. Альтернатива: автоматическое сканирование папок `games/*`. Отвергнуто: при сборке Next.js такое сканирование нестабильно и усложняет отладку.

### D3. Контракт игры - данные плюс функции, без состояния

Игра экспортирует манифест (данные) и компоненты уровней. Компонент уровня получает `onFinish(result)` и отдаёт результат по контракту `game-module-contract`. Ядро не хранит состояние игры. Альтернатива: игра сама пишет в LocalStorage. Отвергнуто: тогда ядро не может гарантировать единый формат и правило `completed=false` не контролируется.

### D4. Слой хранения - одна точка доступа с версией схемы

Все ключи LocalStorage описаны в `core/storage`, у каждого поле `schemaVersion`. Чтение: JSON.parse внутри try/catch, при ошибке возвращается значение по умолчанию. Запись: при QuotaExceededError показывается предупреждение. Если LocalStorage недоступен, модуль работает в памяти текущей сессии (требование core-platform).

Альтернатива: библиотека состояния (Zustand с persist). Не выбрана на этом этапе: одного модуля хватает, а зависимость добавит поверхность для ошибок. Может быть пересмотрена, если состояние станет сложнее.

### D5. Чистые функции для правил

Ачивки, рейтинг диплома и баллы профессий - функции вида `(входные данные) -> результат` без обращения к LocalStorage. Хранение вызывает их и записывает результат. Это позволяет тестировать правила из спеков напрямую (каждый сценарий - тестовый случай).

### D6. Формула баллов профессий

Для каждой профессии `p` и игры `g` с весом `w(g,p)` и результатом `s(g,l)` (доля очков уровня, 0..1) и оценкой `r(g)` (1..5 нормированная к 0..1 как `(r-1)/4`):

```
score(p) = sum over (g,l) of w(g,p) * s(g,l) * q(g)  /  sum over (g,l) of w(g,p)
q(g) = (r(g) - 1) / 4 при наличии оценки, иначе 0.5
```

Лучшее прохождение уровня учитывается один раз (максимум по попыткам). Если по профессии нет ни одного завершённого уровня с весом, балл не считается. Альтернатива: простая сумма очков без оценки. Отвергнуто: оценка игры - ключевой сигнал пользователя, который должен влиять на результат.

Формула - предложение, её стоит проверить на тестовых данных до фиксации в спеке.

### D7. Сертификаты и дипломы как файлы в браузере

Сертификат формируется на клиенте и отдаётся как файл. Серверной генерации нет, потому что данные клиентские.

**Решение (согласовано с пользователем):** формат - автономный HTML-файл для печати (`.html` со встроенными стилями, без внешних ресурсов). Файл открывается в любом браузере, печатается или сохраняется в PDF средствами браузера, текст остаётся выделяемым, зависимостей не добавляется. Разметку строит чистая функция в `core/diplomas` (все значения экранируются), скачивание делает клиентский компонент через `Blob` и временную ссылку. Текст сертификата лежит в `texts/diplomas`.

- Альтернатива: PNG через `<canvas>`. Отвергнуто: ручная раскладка текста и невыделяемый текст.
- Альтернатива: PDF через библиотеку. Может быть выбрана позже без изменения контракта diplomas.

### D8. Тексты и .env

Отображаемый текст - в файлах `texts/` ядра и игр. Режим отладки - переменная `NEXT_PUBLIC_DEBUG` в `.env`. Соответствует CodeStyle.md.

## Risks / Trade-offs

- **[Подделка LocalStorage]** Пользователь может вручную изменить очки и получить диплом. -> Принято как ограничение MVP, пометка на странице дипломов (требование diplomas). Серверная проверка - в будущем change.
- **[Потеря данных при очистке браузера]** Все результаты исчезают. -> Кнопка экспорта/импорта JSON в будущем change; в MVP пользователь видит предупреждение.
- **[Расхождение версий контракта между играми]** Игры написаны по разным версиям контракта. -> Поле `contractVersion` в манифесте и проверка при регистрации (game-module-contract).
- **[Ручной реестр игр]** Забытая строка импорта - игра не появится. -> Тест, который проверяет, что все папки `games/*` подключены в реестр.
- **[Формула баллов]** Веса и оценки могут дать неочевидный результат. -> Вынести веса и формулу в отдельный модуль с тестами и обсудить на тестовых данных.

## Migration Plan

Новый проект, миграций нет. Деплой - статическая сборка Next.js. Откат - возврат предыдущего билда. Схема LocalStorage с `schemaVersion` позволяет при изменениях писать миграцию чтения данных, а не терять результаты.
